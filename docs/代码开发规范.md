## 1. 命名（与 README 对齐并细化）

统一：**类型 / 方法 / 属性 = PascalCase**；**私有字段 = camelCase，推荐 `_` 前缀**（仓库中两套并存时，**新代码统一用 `_camelCase`**）。

| 类别 | 规则 | 示例 |
|------|------|------|
| 命名空间 | PascalCase，与文件夹对应 | `SUNWODA_SEVB.ViewModels.Pages.BoxGluing` |
| 类 | PascalCase | `BoxGluingAcquisitionService` |
| 抽象类 | `Abs` + 名称（历史约定）或语义前缀 | `AbsImageCut` |
| 帮助类 | 名称 + `Helper` | `CsvHelper`、`PythonConfigHelper` |
| 视图 Page/Window | 名称，**无** `VM_` | `BoxGluingMonitoringPage`、`DemoWindow` |
| 视图模型 | **`VM_` + 与 View 对应的名称** | `VM_BoxGluingMonitoringPage` |
| 模型 | 名称 + `Model`（或项目既有后缀） | `ThicknessIMEModel` |
| 接口 | `I` + 名称 | `IBoxGluingAcquisitionService` |
| 枚举 / 结构体 | PascalCase | `DemoEnum`、`WeightInfo` |
| 方法 / 属性 | PascalCase | `StartAsync`、`IsRunning` |
| 私有字段 | `_` + camelCase | `_logger`、`_cts` |
| 常量 | PascalCase 或语义清晰的本地 const | `BlockStart`、`BlockLength` |
| 异步方法 | 后缀 `Async` | `StartAsync`、`OnNavigatedToAsync` |

### 1.1 ViewModel ↔ View（硬规则）

| ViewModel | View |
|-----------|------|
| `…ViewModels.Pages.<项目>.VM_XxxPage` | `…Views.Pages.<项目>.XxxPage` |

- 去掉 `VM_` 前缀；命名空间 `.ViewModels.` → `.Views.`
- `x:Class`、`.xaml.cs` 类名、文件系统名必须一致（大小写敏感踩坑见上手指南）
- `[Module("VM_XxxPage", "菜单中文名")]` 第一个参数与 **VM 类名**一致

### 1.2 项目服务

| 层 | 位置 | 命名 |
|----|------|------|
| 接口 | `SUNWODA_SEVB.Core/Interfaces/Project/<项目>/` | `I{业务}Service` |
| 实现 | `SUNWODA_SEVB/Services/Project/<项目>/` | `{业务}Service` |
| 模型 | `SUNWODA_SEVB.Core/Models/Project/<项目>/` | 与业务语义一致 |
| DI 扩展 | 同实现目录或汇总于 `ProjectServiceCollectionExtensions` | `Add{项目}Services` |

示例（现有）：`IBoxGluingAcquisitionService` → `BoxGluingAcquisitionService`，`AddBoxGluingServices()`。

## 2. 分层与放置

```
Views          → 只负责 UI；code-behind 尽量仅 InitializeComponent
ViewModels     → 页面状态、命令、绑定；通过接口调用服务
Services/Project → 业务/采集/通信/算法编排
Core           → 跨模块接口、模型、特性、VM 基类
PLC / Data / MES / Tool → 基础设施；业务不要复制一套
```

**禁止：**

- View / code-behind 直接读写 PLC、Socket、数据库（除非历史页面且本轮未触碰；**新代码禁止**）
- 在 ViewModel 内堆砌大段协议解析、长时间循环（应下沉到 `Services/Project`）
- 为图省事把产线逻辑写进 `SUNWODA_SEVB.Core` 的无关目录
- 复制粘贴出第二套相同 Service（先搜是否已有接口）

**复杂逻辑路径（架构说明 §13）：**  
业务变复杂 → `Services/Project/<项目>/` + `Core/Interfaces/Project/<项目>/`，再在 `AddProjectServices` / 项目 `AddXxxServices` 注册。

## 3. MVVM 与页面生命周期

- 业务页 ViewModel **必须** `public`，继承 `ViewModelBase`，带 `[Module]`
- 绑定属性使用基类的 `SetProperty(ref field, value)`，保证通知
- 进入/离开页面优先重写异步钩子：`OnNavigatedToAsync` / `OnNavigatedFrom` / `OnCleanupAsync`
- 在 `OnCleanup` / `Dispose` 中：停采集、取消 `CancellationTokenSource`、解订阅事件
- 菜单是否显示看数据库 `workspace_project.is_enabled`，**不是**只靠有 `[Module]`

---

## 4. 依赖注入

- 通过构造函数注入；字段 `private readonly`
- 日志：`ILoggerService<T>`，`T` 为当前类
- 生命周期与现有项目一致：长驻采集/配置类常用 **Singleton**；勿随意把「每页一份」的状态做成错误的单例导致串台
- 新服务：写接口 + 实现 + `AddXxx` 扩展，并挂到既有 `AddProjectServices` 链路
- **禁止**在业务里 `new` 本可由 DI 提供的基础设施（PLC、仓储等），除非工具脚本或测试探针项目

---

## 5. 异步、线程与 UI（上位机）

| 要求 | 说明 |
|------|------|
| 默认 `async Task` | 自写方法避免 `async void`（事件处理除外，且须 try/catch） |
| UI 线程 | 只有 UI 线程改 DependencyObject；跨线程用 `Dispatcher.InvokeAsync` 或项目既有封装 |
| 禁止 | UI 线程同步 `Invoke` 死等后台，造成死锁；后台回调里直接改控件 |
| 高频采集/通信 | 回调只入队，消费者再处理（参考现有采集循环 + CTS） |
| SqlSugar / MySql | **禁止**对同一 `ISqlSugarClient` 做 `Parallel.ForEach` 同步查询；跨线程须 `CopyNew()` 或串行。并发 Open 会报 `Cannot Open when State is Connecting`，模块注册失败则侧边栏空白（见 ModuleManager / MappingRepository） |
| 取消 | 长循环、`HostedService`、采集 Task 必须能响应 `CancellationToken`；禁止 `Thread.Abort` |
| fire-and-forget | 须有异常日志；生命周期归属清晰 |

## 6. 资源与 IDisposable

- 持有 CTS、Task 循环、PLC/Socket、非托管图像/句柄的类型：实现 `IDisposable`（或异步释放约定），在 `Dispose`/`Stop` 中取消并等待退出
- 事件 `+=` 必须有对称 `-=` 或弱事件策略；页面级订阅在 `OnCleanup` 解除
- `using` / `await using` 管理流、短生命周期资源
- 勿在静态列表无限追加运行时曲线/日志对象

### 6.1 长时间运行（采集 / 收图 / OCR）——防内存只涨

现场产线进程常连续跑数小时～数天，下列模式视为 **P1（可升 P0）**：

| 检查 | 要求 |
|------|------|
| **只增不减的集合** | `ConcurrentDictionary` / `HashSet` / `List` 若按文件路径、SN、帧 ID 入队去重或缓存，必须有：处理完成后移除、TTL 过期、或按回看天数裁剪。禁止「只 TryAdd 永不 Remove」 |
| **已处理 / 索引落盘** | 本地 idx/状态文件对应的内存表须**运行期定期裁剪**（不能仅在 Open 时裁一次） |
| **Halcon `HObject`** | `ReadImage` / 算法 `out HObject` 必须在 `finally` 中 `Dispose`；长跑建议关闭临时缓存（如 `temporary_mem_cache=false`），与视觉资料约定一致 |
| **UI 预览图** | `BitmapImage` 必须 `DecodePixelWidth/Height` 缩略；同路径勿重复解码；禁止每帧把原分辨率大图塞进绑定 |
| **UI 高频刷新** | 每帧重建图表/大集合绑定须节流；日志/结果表须有上限并淘汰旧项 |
| **未完成业务对象** | Pack/电芯等聚合字典须有超时收口，避免「永远不齐套」永久占内存 |
| **补扫 / 轮询** | 枚举目录时尽早跳过已处理路径，避免每次把全量路径列表堆进内存 |

**样板反例（已在 ZZSIX 修过）**：收图 `_seen` 只进不出 + 补扫先入 `_seen` 再查已处理 → 长时间运行工作集持续爬升。

### 6.2 FileSystemWatcher / 目录监控——防丢事件（P1，可升 P0）

整夹复制、子目录突发写入时，易出现 `InternalBufferOverflowException`，**后续文件静默丢失**（界面只检到少量图）。触及 `FileSystemWatcher` / 目录监控变更时 **必查**：

| 检查 | 要求 |
|------|------|
| **回调只入队** | `Created`/`Renamed`/`Changed` 内禁止 `Sleep`、等文件写完、`ImRead`/`ReadImage`、跑算法、写盘；只做路径校验 + 入业务队列后立即返回 |
| **就绪与读图** | `WaitFileReady` / 读图 / 推理放在**消费线程**（队列消费者），不得占用 Watcher 回调线程 |
| **缓冲** | 显式设置 `InternalBufferSize`（建议 `64 * 1024`，系统上限）；默认约 8KB 不够整夹突发 |
| **子目录** | 业务需要含子目录时 `IncludeSubdirectories = true`；「导入文件夹」枚举须与监控语义一致（通常 `SearchOption.AllDirectories`） |
| **Error 恢复** | 订阅 `Error`；遇 `InternalBufferOverflowException` 须：重启 Watcher + 对监控根做一次符合规则的全量补扫入队（去重），禁止只弹红字不补捞 |
| **去重集合** | 入队去重字典须在处理完成/失败后 Remove（与 §6.1 一致），避免只增不减 |

**样板反例（已在 NCLCCT 修过，2026-09-22）**：回调内 `Sleep`+`WaitFileReady`+`ImRead` → 整夹复制触发缓冲溢出 → 只入队一两张；Error 仅 Growl 不补扫。

**审查级别**：确认会丢检/丢事件 → **P1**；产线连续漏检导致批量误放行风险 → 可升 **P0**。

### 6.3 关键结果落盘 / 云端资源下载——原子覆盖（P1）

覆盖**正式文件**（检测结果 CSV、模型 `.onnx`、算法 DLL 等）时，禁止边下载/边合并边直接改写目标文件：中途失败、断电、Excel 占用会导致**半截文件顶替可用旧文件**。触及「写正式路径 / 覆盖下载」时 **必查**：

#### 6.3.1 云端资源 / 大文件下载（模型、DLL 等）

| 检查 | 要求 |
|------|------|
| **临时后缀** | 先写到同目录旁路文件，推荐正式名 + `.downloading`（例：`model_hw.onnx.downloading`） |
| **成功再替换** | 下载完整且校验通过（如 PE 头 `MZ`、长度大于 0）后，再 `Delete` 旧正式文件并 `Move` 临时文件覆盖 |
| **失败保留旧件** | 下载失败 / 校验失败：删除临时文件，**不得**清空或半写正式文件；若业务允许，可回退加载本机旧文件并告警 |
| **进度与超时** | 大文件用流式读写 + 界面进度；`HttpClient` 勿用过短默认超时（大模型易 `TaskCanceledException`）；超时策略与业务约定一致 |

**样板（NCLCCT，2026-09-23）**：本机无 `NJCT.dll` / `model_hw.onnx` 时才云端下载 → `*.downloading` → 落盘正式路径并清理临时文件；本机已有则直接加载。

#### 6.3.2 检测结果 CSV（现场常被 Excel 打开）

| 检查 | 要求 |
|------|------|
| **勿直写被锁文件** | Excel 打开正式 CSV 时直接 `File.Append` / `StreamWriter` 易失败或写花；须有旁路策略 |
| **推荐两段式** | ① 新行先追加到旁路缓存（如同名 `.cache` 或等价）；② 再经**另一临时文件**合并「正式 CSV 已有内容 + 缓存」，成功后原子替换正式 CSV，清空/删除缓存 |
| **合并失败** | 保留缓存与旧正式文件，下次再合；禁止「合并失败仍截断正式 CSV」 |
| **表头** | 新建正式文件时写表头；合并时勿重复插表头 |

**样板（NCLCCT，2026-09-23）**：`Gap检测结果.csv` → 先写 `.cache` → 临时合并文件 → 覆盖正式 CSV（Excel 占用时不丢行）。

**审查级别**：会毁掉现场唯一可用模型/DLL，或弄丢当日 CSV 行 → **P1**；导致批量误用坏模型/坏结果放行 → 可升 **P0**。

## 7. PLC / 设备 / 配置真相源

- **点位、IP、工艺阈值**：以 `docs/<项目>/` 下 CSV 或项目配置服务为准，**禁止臆造**
- 写设备前考虑互锁/模式（自动·手动、权限）；失败策略要明确，禁止「吞异常后继续写」
- 地址常量宜集中（如采集服务内 `BlockStart`），并与 CSV 注释或配置可对照
- 日志可定位，但避免高频打满磁盘或打印密钥

---

## 8. 异常与日志

- 边界（通信、文件、外部 DLL）捕获后：**记日志 + 对用户/状态有反馈**；禁止空 `catch`
- 区分可恢复与致命；取消用 `OperationCanceledException` 正常路径处理，勿当故障刷屏
- 使用注入的 `ILoggerService<T>`，与项目现有级别习惯一致

---

## 9. 注释与可读性

- 注释写**为什么 / 协议约束 / 时序**，不写「给 x 赋值」式废话
- 公共服务类顶部可用简短摘要（采样周期、块地址范围等），见 `BoxGluingAcquisitionService`
- 魔法数：命名 const，或来自配置；工艺阈值不进硬编码（除非临时模拟且注释标明）
- 单方法过长且含设备写：拆分私有方法，保持主流程可读
- **中文**：面向现场的日志、菜单、`[Module]` 显示名用中文；代码标识符用英文

---

## 10. XAML

- `x:Class` 与命名空间、类名完全一致
- 业务逻辑不放 code-behind
- 绑定到 VM 属性；需要通知的集合用可观察集合（与邻页一致）
- 样式优先复用主题/现有控件，避免单页内联一大坨重复样式（除非该产线已有模式）

---

## 11. 工程与提交卫生

- 不提交：`bin/`、`obj/`、用户本地 `.user`、现场大包、密钥明文、大量日志
- 不提交无意义的整文件格式化刷屏（与功能无关的 whitespace-only）
- 改公共框架（Core/PLC/App 启动等）须在版本变更或审查说明里写清**影响面**
- AI/人工改业务码后：更新该项目进度存档 + 版本变更记录（见 Agent 规程）

---

## 12. 格式（无 EditorConfig 时的约定）

仓库目前无统一 `.editorconfig` 时，**新代码**：

- 缩进与**同文件 / 同目录**现有文件一致（多为 4 空格）
- 大括号与邻接 C# 文件一致（常见 Allman 风格：`{` 单独一行）
- 文件编码 UTF-8；换行与仓库一致
- using：需要的保留；不要为「干净」大规模重排无关 using 造成嘈杂 diff

（若日后引入 `.editorconfig` / `dotnet format`，以工具配置为准，并修订本节。）
