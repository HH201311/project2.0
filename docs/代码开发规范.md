### 0.3 优先级原则

1. **红线 > 写法约定 > 邻接代码风格**。
2. 写法层面与邻接代码保持一致优先，不另造一套风格；但**邻接旧代码违反红线时，新代码不得照抄**。
3. 与一键审查或其他文档冲突时，以**更严的安全项**为准（设备误写、死锁、泄漏、丢数据）。

### 0.4 级别定义

| 级别 | 含义 | 处置 |

| **P2** | 可观测性、可读性、命名、文档收尾缺陷 | 应修复，可排期 |

# 第一篇 写法约定

## 1. 命名（与 README 对齐并细化）

统一：**类型 / 方法 / 属性 = PascalCase**；**私有字段 = camelCase，推荐 `_` 前缀**（仓库中两套并存时，**新代码统一用 `_camelCase`**）。

| 类别 | 规则 | 示例 |
|------|------|------|
| 命名空间 | PascalCase，与文件夹对应 | `SUNWODA_SEVB.ViewModels.Pages.BoxGluing` |
| 类 | PascalCase | `BoxGluingAcquisitionService` |
| 抽象类 | `Abs` + 名称（历史约定）或语义前缀 | `AbsImageCut` |
| 帮助类 | 名称 + `Helper` | `CsvHelper`、`PythonConfigHelper` |
| 视图 Page/Window | 名称，**无** `VM_` | `BoxGluingMonitoringPage`、`DemoWindow` |
| 视图模型 | **`VM_` + 与 View 对应的名称** | `VM_BoxGluingMonitoringPage` |
| 模型 | 名称 + `Model`（或项目既有后缀） | `ThicknessIMEModel` |
| 接口 | `I` + 名称 | `IBoxGluingAcquisitionService` |
| 枚举 / 结构体 | PascalCase | `DemoEnum`、`WeightInfo` |
| 方法 / 属性 | PascalCase | `StartAsync`、`IsRunning` |
| 私有字段 | `_` + camelCase | `_logger`、`_cts` |
| 常量 | PascalCase 或语义清晰的本地 const | `BlockStart`、`BlockLength` |
| 异步方法 | 后缀 `Async` | `StartAsync`、`OnNavigatedToAsync` |
| 带单位的量 | 名称体现单位（工程值 / 原始值须可区分） | `SpeedMmPerSec`、`PressureRaw` |

### 1.1 ViewModel ↔ View（硬规则）

| ViewModel | View |
|-----------|------|
| `…ViewModels.Pages.<项目>.VM_XxxPage` | `…Views.Pages.<项目>.XxxPage` |

- 去掉 `VM_` 前缀；命名空间 `.ViewModels.` → `.Views.`
- `x:Class`、`.xaml.cs` 类名、文件系统名必须一致（大小写敏感踩坑见上手指南）
- `[Module("VM_XxxPage", "菜单中文名")]` 第一个参数与 **VM 类名**一致

### 1.2 项目服务

| 层 | 位置 | 命名 |
|----|------|------|
| 接口 | `SUNWODA_SEVB.Core/Interfaces/Project/<项目>/` | `I{业务}Service` |
| 实现 | `SUNWODA_SEVB/Services/Project/<项目>/` | `{业务}Service` |
| 模型 | `SUNWODA_SEVB.Core/Models/Project/<项目>/` | 与业务语义一致 |
| DI 扩展 | 同实现目录或汇总于 `ProjectServiceCollectionExtensions` | `Add{项目}Services` |

示例（现有）：`IBoxGluingAcquisitionService` → `BoxGluingAcquisitionService`，`AddBoxGluingServices()`。

---

## 2. 分层与放置

```text
Views            → 只负责 UI；code-behind 尽量仅 InitializeComponent
ViewModels       → 页面状态、命令、绑定；通过接口调用服务
Services/Project → 业务/采集/通信/算法编排
Core             → 跨模块接口、模型、特性、VM 基类
PLC / Data / MES / Tool → 基础设施；业务不要复制一套
```

**禁止（新代码违反按 P1 计）：**

- View / code-behind 直接读写 PLC、Socket、数据库（历史页面且本轮未触碰除外）
- 在 ViewModel 内堆砌大段协议解析、长时间循环（应下沉到 `Services/Project`）
- 为图省事把产线逻辑写进 `SUNWODA_SEVB.Core` 的无关目录
- 复制粘贴出第二套相同 Service（先搜是否已有接口）

**复杂逻辑路径（架构说明 §13）：**  
业务变复杂 → `Services/Project/<项目>/` + `Core/Interfaces/Project/<项目>/`，再在 `AddProjectServices` / 项目 `AddXxxServices` 注册。

---

## 3. MVVM 与页面生命周期

- 业务页 ViewModel **必须** `public`，继承 `ViewModelBase`，带 `[Module]`
- 绑定属性使用基类的 `SetProperty(ref field, value)`，保证通知
- 进入/离开页面优先重写异步钩子：`OnNavigatedToAsync` / `OnNavigatedFrom` / `OnCleanupAsync`
- 在 `OnCleanup` / `Dispose` 中：停采集、取消 `CancellationTokenSource` 并等待退出、解订阅事件（对应 G-03、F-09）
- 有副作用的命令须有忙碌标志或 `CanExecute` 联动（对应 F-05）
- 菜单是否显示看数据库 `workspace_project.is_enabled`，**不是**只靠有 `[Module]`

---

## 4. 依赖注入

- 通过构造函数注入；字段 `private readonly`
- 日志：`ILoggerService<T>`，`T` 为当前类
- 生命周期与现有项目一致：长驻采集/配置类常用 **Singleton**；勿随意把「每页一份」的状态做成错误的单例导致串台
- 新服务：写接口 + 实现 + `AddXxx` 扩展，并挂到既有 `AddProjectServices` 链路
- **禁止**在业务里 `new` 本可由 DI 提供的基础设施（PLC、仓储等），除非工具脚本或测试探针项目
- 新增第三方依赖遵守 A-08

---

## 5. XAML

- `x:Class` 与命名空间、类名完全一致
- 业务逻辑不放 code-behind
- 绑定到 VM 属性；需要通知的集合用可观察集合（与邻页一致）；后台线程改集合遵守 F-03
- 样式优先复用主题/现有控件，避免单页内联一大坨重复样式（除非该产线已有模式）
- 设备离线、危险参数的显示遵守 B-05

---

## 6. 注释与可读性

- 注释写**为什么 / 协议约束 / 时序 / 单位**，不写「给 x 赋值」式废话
- 公共服务类顶部可用简短摘要（采样周期、块地址范围等），见 `BoxGluingAcquisitionService`
- 魔法数：命名 const，或来自配置；硬件与工艺参数不得硬编码（见 B-08）
- 单方法过长且含设备写：拆分私有方法，保持主流程可读
- 被忽略的异常须注释理由（见 A-01）
- **中文**：面向现场的日志、菜单、`[Module]` 显示名用中文；代码标识符用英文

---

## 7. 格式（无 EditorConfig 时的约定）

仓库目前无统一 `.editorconfig` 时，**新代码**：

- 缩进与**同文件 / 同目录**现有文件一致（多为 4 空格）
- 大括号与邻接 C# 文件一致（常见 Allman 风格：`{` 单独一行）
- 文件编码 UTF-8；换行与仓库一致
- using：需要的保留；不要为「干净」大规模重排无关 using 造成嘈杂 diff

（若日后引入 `.editorconfig` / `dotnet format`，以工具配置为准，并修订本节。）

---

## 8. 工程与提交卫生

- 不提交：`bin/`、`obj/`、用户本地 `.user`、现场大包、密钥明文（见 E-04）、大量日志
- 不提交无意义的整文件格式化刷屏（与功能无关的 whitespace-only）
- 改公共框架（Core/PLC/App 启动等）须在版本变更或审查说明里写清**影响面**
- AI/人工改业务码后：更新该项目进度存档 + 版本变更记录（见 Agent 规程）

# 第二篇 上位机红线

## 9. 红线条款（A–H）

> 供人工与 AI 生成代码、审查代码时**逐条对照**。命中任一条即视为不合规，必须返工。  
> 类别：`A` 异常底线｜`B` 设备与状态｜`C` 通信与协议｜`D` 数据与持久化｜`E` 安全与联锁｜`F` 线程与重入｜`G` 取消与资源｜`H` 日志与可观测。  
> 级别见 §0.4；`P1↑` 的升级条件写在条款内。

### A 异常底线

> 本质：故障必须可见、可恢复、可追溯。

| 编号 | 触发场景 | ❌ 不可这样做 | ✅ 必须这样做 | 级别 |
|------|----------|---------------|---------------|------|
| A-01 | 捕获异常 | 写空 `catch {}`；catch 内无日志、无重抛、无状态反馈；catch 后只写 `//TODO` 或只 `return;` | 至少做三件事之一：① 记日志（含上下文与堆栈）② 向上抛出或包装后抛出 ③ 执行明确的补偿或降级动作并记录。仅释放动作与取消路径可忽略，且须注释理由 | P0 |
| A-02 | 中止执行 | 因参数非法、未连接、数据缺失而 `return`，不留日志或状态 | 记日志并返回明确结果，让调用方分得清「已完成」与「未执行」 | P1 |
| A-03 | 反馈结果 | 先报「已下发 / 已发送 / 已完成」，再做可能失败的操作 | 只在确认成功后报成功，失败时报失败原因 | P0 |
| A-04 | 异常分支 | 异常后既不中止也不告警，继续走主流程；不区分可恢复与致命 | 要么中止并上报，要么明确降级并记录 | P1 |
| A-05 | 调用底层库 | 调用 HslCommunication / Halcon / Python.NET / Http 后不检查返回值 | 必须查 `IsSuccess`、错误码或 null——这类库失败时不抛异常，不检查等于没处理 | P1 |
| A-06 | 全局兜底 | 程序入口不注册全局异常兜底；或依赖兜底存活后继续跑生产流程 | 入口必须注册域异常、UI 调度异常、未观察任务异常三类兜底；致命异常后停止本流程并提示用户，不得带病继续 | P0 |
| A-07 | 启动自检 | 配置、路径、数据库、设备通信不检查就直接进入主流程，起来后不能用也不提示 | 启动时逐项自检配置合法性、路径可写、数据库可访问、设备可通信，每项给出明确结论与处置建议 | P1 |
| A-08 | 引入依赖 | 直接 new 一个新库、运行时动态下载 DLL（业务资源下载见 D-05）、不锁版本 | 只用既有基础设施与锁定版本的程序包；新增依赖须说明理由并固定版本 | P1 |

### B 设备与状态

> 本质：写入判成败、回读确认、界面不撒谎、点位不臆造。

| 编号 | 触发场景 | ❌ 不可这样做 | ✅ 必须这样做 | 级别 |
|------|----------|---------------|---------------|------|
| B-01 | 写设备 | 写完 PLC / MES 不判成败，或失败后照常走下一步 | 依返回值判定：失败 → 记录 → 中止或明确上报 | P0 |
| B-02 | 写关键信号 | 写心跳 / 允许 / 报警 / 复位后即认为已生效 | 读回或取设备回执确认已在位；下位机会自行清零的信号尤其不可假设成功 | P0 |
| B-03 | 写设备前置条件 | 设备运行中或存在报警时照常下发参数 | 写入前校验设备状态与模式（自动 / 手动）、权限及联锁条件；不满足即拒绝下发并提示原因 | P0 |
| B-04 | 下发数值 | 用来源不明的地址；值超量程；不按设备分辨率舍入；类型宽度不匹配（如 3000 写入 16 位有符号）；寄存器原始值与工程值差 1000 倍等量纲错误 | 地址取自点位表；值校验量程与分辨率，按分辨率舍入后下发；超范围拒绝下发；原始值与工程值经唯一换算函数转换，单位写进命名与注释 | P0 |
| B-05 | 显示状态 | 离线后仍显示最后一次读到的值且无标识；危险参数只显示设定值 | 离线时置灰显示「不可用」；危险参数区分「设定值 / 实际值」，以设备读回值为准 | P0 |
| B-06 | 用读回数据 | 读设备返回 null / 空集合 / 失败时，当 0 或旧值继续判定、写结果 | 标记本轮数据无效，不参与判定、不写结果库，并记录 | P1 |
| B-07 | 传感器数值 | 拿到设备数值直接参与判定，不判合理范围（负值、超量程、NaN、突变） | 判断是否在物理合理范围内；异常值标记无效，不参与判定并记录 | P1 |
| B-08 | 硬件参数 | IP、端口、串口号、波特率、数据库连接串、超时值、工艺参数（速度 / 位置 / 扭矩 / 节拍）写死在源码里 | 全部外部化为配置或参数表并带默认值；启动时校验，缺失或非法即拒绝启动 | P1 |
| B-09 | 点位与工艺真相源 | 凭经验、示例或相似产线臆造 PLC 点位、IP、工艺阈值并用于读写 | 以 `docs/<项目>/` 下 CSV 或项目配置服务为唯一真相源；查不到即标「待人工确认」，不得进入读写路径；地址常量集中定义（如采集服务内 `BlockStart`）并可与 CSV 对照 | P0 |

### C 通信与协议

> 本质：每次收发都有超时、校验、失败路径。

| 编号 | 触发场景 | ❌ 不可这样做 | ✅ 必须这样做 | 级别 |
|------|----------|---------------|---------------|------|
| C-01 | 通信超时 | 不设超时；或把超时设为 0（0 即无限期阻塞）；串口不设 `ReadTimeout` / `WriteTimeout` | 连接、读、写、握手、等应答都必须有显式有限超时，且超时值来自配置而非魔法数字；令牌能在超时时真正中断操作 | P0 |
| C-02 | 解析通信帧 | 把 Read 到的字节直接当业务数据用（无帧头、无长度、无校验）；不处理粘包、半包、超长帧 | 必须做帧头帧尾识别、长度字段校验、校验和（CRC / LRC / Sum）校验、粘包拆包处理；非法长度或校验失败的帧丢弃并告警，计入错误指标 | P0 |
| C-03 | 长连接 | 连上就完事，不检测连接状态，断了不重连 | 心跳或周期探活 + 断线检测 + 带退避的自动重连；重连后重新握手、重新订阅、回读必要状态；界面显示连接状态与最近成功通信时间 | P1 |
| C-04 | 失败重试 | 无上限重试；无退避连发；忙等待 `while(!ok){}`；失败一声不响 | 重试须有最大次数或最大时长、退避间隔（建议指数退避 + 抖动，避免多工位同步冲击）、可取消；耗尽后进入明确失败状态并告警 | P0 |
| C-05 | 判设备状态 | `switch` 不写 `default`；或 `default` 按「正常 / 通过」处理 | 必须有 `default`，且走未知或异常分支：记录原始值、界面提示、不推进危险动作 | P1 |
| C-06 | 协议返回码 | 只处理「成功」分支，未知错误码当正常 | 完整映射成功、设备忙、参数非法、超时、校验错、未知等状态，未知码必须记录原始值 | P1 |
| C-07 | 状态机 | 存在无法退出的状态；状态跳转无超时 | 每个状态必须定义异常进入路径与超时退出路径，禁止存在无法退出的状态 | P1 |

### D 数据与持久化

> 本质：坏数据不进门，掉电不坏数据，事件不丢。

| 编号 | 触发场景 | ❌ 不可这样做 | ✅ 必须这样做 | 级别 |
|------|----------|---------------|---------------|------|
| D-01 | 写配置文件 | 用覆盖写保存配置、配方、标定参数、生产统计（如 `File.WriteAllText`），写到一半掉电即文件损坏 | 原子写入：写临时文件 → `Flush(true)` 真正落盘 → `File.Replace` 原子替换；替换前保留 `.bak` | P0 |
| D-02 | 读配置文件 | 读取时不校验完整性，损坏即抛异常到界面；启动阶段直接崩溃 | 读取失败须回退到 `.bak` 或默认值并告警；禁止让配置损坏导致启动崩溃 | P0 |
| D-03 | 精度与单位 | 浮点用 `==` 比较；用浮点累加做计数或累计 | 浮点用容差比较；累计量用 `decimal` 或整数最小单位 | P1 |
| D-04 | 用设备数据取值 | 用设备返回值、帧长、协议字段直接做数组索引 | 取值前判 null、长度与范围；坏帧丢弃并记录，绝不越界 | P0 |
| D-05 | 覆盖正式文件 / 云端下载 | 边下载 / 边合并直接改写正式文件（模型 `.onnx`、算法 DLL、检测结果 CSV）；失败或断电后半截文件顶替可用旧件；Excel 打开 CSV 时仍直写 | 先写旁路临时文件，校验通过后再替换正式文件；失败保留旧正式文件；结果 CSV 走「缓存 + 临时合并 + 替换」两段式。详见 **R3**。**升级条件**：导致批量误用坏模型 / 坏结果放行 | P1↑ |
| D-06 | 目录监控 | `FileSystemWatcher` 回调内 `Sleep` / 等文件就绪 / 读图 / 跑算法；使用默认约 8KB 缓冲；`Error` 只弹窗不补扫 | 回调只入队；`InternalBufferSize = 64 * 1024`；溢出后重启 Watcher 并全量补扫入队（去重）。详见 **R2**。**升级条件**：产线连续漏检导致批量误放行 | P1↑ |

### E 安全与联锁

> 本质：危险动作有闸门，行为可追溯。

| 编号 | 触发场景 | ❌ 不可这样做 | ✅ 必须这样做 | 级别 |
|------|----------|---------------|---------------|------|
| E-01 | 危险动作 | 下发参数并保存、回零、标定、配方切换、启动运行、修改安全阈值、清报警复位、手动输出等操作，无权限校验、无联锁校验、无二次确认 | 四者齐备：① 权限校验 ② 合法性 / 范围校验 ③ 前置条件 / 联锁校验（运行中或有报警时禁止）④ 二次确认并显示新旧值。上位机联锁是防呆，**不能替代设备硬联锁，但不可省** | P0 |
| E-02 | 危险动作留痕 | 危险动作执行后无任何记录，事后无法定责与复盘 | 记录操作人、时间、改前值、改后值、结果；越权尝试也必须记录 | P0 |
| E-03 | 写安全参数 | 写完安全限值不回读校验 | 下发后回读比对，不一致即报失败并提示检查设备 | P0 |
| E-04 | 敏感信息 | 把密码、密钥、Token 写进日志、明文配置或提交进仓库；日志记完整个人信息 | 密码走加密存储；日志中敏感字段一律脱敏或不记；日志只记「谁、何时、做了什么、结果」 | P0 |

### F 线程与重入

> 本质：UI 永不阻塞，任务有界，回调不可重入，共享资源串行。

| 编号 | 触发场景 | ❌ 不可这样做 | ✅ 必须这样做 | 级别 |
|------|----------|---------------|---------------|------|
| F-01 | 写异步方法 | 自写方法用 `async void` | 一律 `async Task`；仅事件处理可 `async void`，且函数体须整体 try/catch | P1 |
| F-02 | UI 线程 | 在 UI 线程上 `.Result` / `.Wait()` / `Thread.Sleep` / 同步 `Invoke` 死等后台 | 一律 `await`；需要回 UI 线程用异步调度，不在 UI 线程同步等待 | P0 |
| F-03 | 后台改界面 | 在非 UI 线程访问控件或界面绑定的集合；直接用 `Application.Current` 而不判空 | 用 `Dispatcher.InvokeAsync` 或项目既有封装回 UI 线程再改，并处理 `Application.Current` 为 null 的情况 | P1 |
| F-04 | 定时器回调 | 在 tick 回调里做耗时操作（读设备、写库、算法、发 HTTP）且无防重入，上一轮未完成下一轮又进来 | 回调只入队或置标志；或用防重入标志；或 `AutoReset = false` 处理完再手动启动 | P0 |
| F-05 | 按钮命令 | 有副作用的按钮（下发 / 启动 / 清数据 / 复位 / 上传）无忙碌标志，操作员连点即重复执行 | 加忙碌标志或 `CanExecute` 联动，执行中禁用按钮 | P1 |
| F-06 | 并发写设备 | 多处代码（多线程、多页面、定时器与按钮）同时写同一 PLC 地址；读-改-写不加锁 | 单一出口 + `SemaphoreSlim(1,1)` 串行化；读-改-写整段在锁内 | P0 |
| F-07 | 创建线程 / 任务 | 每个事件或每次请求都 `new Thread` / `Task.Run`，无上限无回收 | 用长驻后台服务或单循环；确需并发须有界（信号量 / 队列 / 线程池） | P1 |
| F-08 | 共享状态 | 裸 int 计数器跨线程 `++`；共享 `List` / `Dictionary` 多线程读写不加锁；持锁期间做 IO、改 UI 或等锁 | 计数用 `Interlocked`；共享集合用并发容器或全程加锁；锁内不做 IO / UI / 等锁；跨线程传可变对象先做快照 | P1 |
| F-09 | 事件订阅 | `+=` 订阅事件后不 `-=`，页面或对象反复创建后无法回收 | 订阅必须对称取消订阅（或弱事件策略）；页面级订阅在 `OnCleanup` 解除 | P1 |
| F-10 | 高频回调 | 在采集 / 通信 / 设备订阅回调里做解析、写库、算法、改 UI | 回调只入队，由消费者线程处理（参考现有采集循环 + CTS）；队列有界，满时的丢弃策略须记录 | P1 |
| F-11 | 数据库客户端并发 | 对同一 `ISqlSugarClient` 做 `Parallel.ForEach` / 多线程同步查询 | 跨线程用 `CopyNew()` 或串行访问。并发 Open 会报 `Cannot Open when State is Connecting`，模块注册失败则侧边栏空白（见 ModuleManager / MappingRepository） | P1 |

### G 取消与资源

> 本质：任务有界可停，资源必释放，长跑内存不涨。

| 编号 | 触发场景 | ❌ 不可这样做 | ✅ 必须这样做 | 级别 |
|------|----------|---------------|---------------|------|
| G-01 | 长循环 | 用 `while (true)` 且不检查取消令牌；用 `Thread.Abort` 强杀 | 长循环、`HostedService`、采集 Task 必须响应 `CancellationToken`；禁止 `Thread.Abort` | P1 |
| G-02 | 处理取消异常 | 把取消异常并入 `catch (Exception)` 后记 Error、写库、触发报警或重连 | `catch (OperationCanceledException)` 必须写在 `catch (Exception)` 之前，且不写库、不报警 | P0 |
| G-03 | 停止与释放 | 只 `Cancel()` 就释放资源、关连接、写文件收尾 | 先 `Cancel`，再 `await` 任务真正退出，然后才释放资源与收尾；持有 CTS / 循环 / 设备句柄的类型实现 `IDisposable` 或异步释放约定 | P0 |
| G-04 | 丢弃任务 | 用 `_ = XxxAsync()` 丢弃任务，异常无人接 | 丢弃的任务内部必须有顶层 try/catch 或异常日志，且生命周期归属清晰 | P1 |
| G-05 | 释放设备资源 | 串口 / Socket / 文件流 / 命令 / 图像句柄用完不 `Dispose`；异常路径漏释放 | 全部 `using` / `await using` / `Dispose`，在 `finally` 中释放；异常路径同样要释放 | P0 |
| G-06 | 长跑内存 | 去重 / 缓存集合只增不减；静态列表无限追加曲线 / 日志对象；图像对象用完不释放；预览图不解码缩略；聚合对象永无超时收口；已处理索引只在启动时裁剪一次 | 集合处理后移除或设 TTL 裁剪，索引运行期定期裁剪；图像在 `finally` 释放；预览图缩略；聚合对象设超时收口。详见 **R1** | P0 |

### H 日志与可观测

> 本质：现场可诊断，异常不静默。

| 编号 | 触发场景 | ❌ 不可这样做 | ✅ 必须这样做 | 级别 |
|------|----------|---------------|---------------|------|
| H-01 | 记异常日志 | 只记 `ex.Message` 丢堆栈；不带设备、工位、业务 ID 上下文；异常只写文件不写库 | 用注入的 `ILoggerService<T>` 传 ex 对象；日志含时间（含毫秒）、设备标识、工位、用户、关键业务 ID（条码 / 批次 / 配方名）；异常写入数据库 | P1 |
| H-02 | 必记事件 | 启动退出、连接断开、重连、危险动作及其结果、状态跳转、配置变更、登录登出与越权尝试都不记 | 上述事件必须留痕；禁止「出事了什么都没有」 | P1 |
| H-03 | 循环内记日志 | 采集 / 轮询循环里每轮都记异常，把库和磁盘打满 | 相同原因降频记录，并在异常后加退避延时；恢复时记一条恢复日志 | P1 |
| H-04 | 异常反馈 | 影响生产的异常只写日志，界面毫无提示 | 影响生产的异常必须反映到界面或状态栏，并给出处置建议 | P1 |
| H-05 | 日志落盘 | 日志无大小上限与归档份数，长期运行撑爆磁盘导致软件崩溃 | 配置按天 / 按大小轮转 + 单文件上限 + 保留份数上限；磁盘剩余空间纳入告警 | P1 |
| H-06 | 运行指标 | 出问题时没有任何可看的数据，只能靠现场口述；断了几次、超时几次都答不上来 | 提供并可在界面 / 日志查看：收发帧数、校验错误数、超时次数、重连次数、当前连接状态、最近一次成功通信时间、内存与线程 / 句柄数、日志盘剩余空间 | P2 |

# 第三篇 专项细则

> 现场踩坑沉淀的**场景化**要求。红线条款给出「一句话底线」，本篇给出逐项检查表与样板反例。变更触及对应场景时必读。

## 10. 专项细则（R1 起）

### R1 长时间运行（采集 / 收图 / OCR）——防内存只涨

| 项 | 内容 |
|----|------|
| 关联条款 | G-06、G-05 |
| 触发场景 | `Services/Project/**` 收图 / 管线 / 视觉、补扫、OCR、预览绑定 |
| 级别 | 按 G-06 |

现场产线进程常连续跑数小时～数天，逐项检查：

| 检查 | 要求 |
|------|------|
| **只增不减的集合** | `ConcurrentDictionary` / `HashSet` / `List` 若按文件路径、SN、帧 ID 入队去重或缓存，必须有：处理完成后移除、TTL 过期、或按回看天数裁剪。禁止「只 TryAdd 永不 Remove」 |
| **已处理 / 索引落盘** | 本地 idx / 状态文件对应的内存表须**运行期定期裁剪**（不能仅在 Open 时裁一次） |
| **Halcon `HObject`** | `ReadImage` / 算法 `out HObject` 必须在 `finally` 中 `Dispose`；长跑建议关闭临时缓存（如 `temporary_mem_cache=false`），与视觉资料约定一致 |
| **UI 预览图** | `BitmapImage` 必须 `DecodePixelWidth/Height` 缩略；同路径勿重复解码；禁止每帧把原分辨率大图塞进绑定 |
| **UI 高频刷新** | 每帧重建图表 / 大集合绑定须节流；日志 / 结果表须有上限并淘汰旧项 |
| **未完成业务对象** | Pack / 电芯等聚合字典须有超时收口，避免「永远不齐套」永久占内存 |
| **补扫 / 轮询** | 枚举目录时尽早跳过已处理路径，避免每次把全量路径列表堆进内存 |

**样板反例（ZZSIX，已修）**：收图 `_seen` 只进不出 + 补扫先入 `_seen` 再查已处理 → 长时间运行工作集持续爬升。

### R2 FileSystemWatcher / 目录监控——防丢事件

| 项 | 内容 |
|----|------|
| 关联条款 | D-06、F-10、G-06 |
| 触发场景 | 变更触及 `FileSystemWatcher`、`OnCreated`、`IncludeSubdirectories`、`InternalBuffer`、监控路径切换、补扫 |
| 级别 | P1↑（产线连续漏检导致批量误放行时升 P0） |

| **子目录** | 业务需要含子目录时 `IncludeSubdirectories = true`；「导入文件夹」枚举须与监控语义一致（通常 `SearchOption.AllDirectories`） |
| **Error 恢复** | 订阅 `Error`；遇 `InternalBufferOverflowException` 须：重启 Watcher + 对监控根做一次符合规则的全量补扫入队（去重），禁止只弹红字不补捞 |
| **去重集合** | 入队去重字典须在处理完成 / 失败后 Remove（与 R1 一致），避免只增不减 |

**样板反例（NCLCCT，2026-09-22，已修）**：回调内 `Sleep` + `WaitFileReady` + `ImRead` → 整夹复制触发缓冲溢出 → 只入队一两张；Error 仅 Growl 不补扫。

### R3 关键结果落盘 / 云端资源下载——原子覆盖

| 项 | 内容 |
|----|------|
| 关联条款 | D-05、D-01 |
| 触发场景 | 写正式路径、覆盖下载模型 / DLL、检测结果 CSV 追加 / 合并 |
| 级别 | P1↑（导致批量误用坏模型 / 坏结果放行时升 P0） |

覆盖**正式文件**时，禁止边下载 / 边合并边直接改写目标文件：中途失败、断电、Excel 占用会导致**半截文件顶替可用旧文件**。

#### R3.1 云端资源 / 大文件下载（模型、DLL 等）

| 检查 | 要求 |
|------|------|
| **临时后缀** | 先写到同目录旁路文件，推荐正式名 + `.downloading`（例：`model_hw.onnx.downloading`） |
| **成功再替换** | 下载完整且校验通过（如 PE 头 `MZ`、长度大于 0）后，再替换正式文件 |
| **失败保留旧件** | 下载失败 / 校验失败：删除临时文件，**不得**清空或半写正式文件；若业务允许，可回退加载本机旧文件并告警 |
| **进度与超时** | 大文件用流式读写 + 界面进度；`HttpClient` 勿用过短默认超时（大模型易 `TaskCanceledException`）；超时策略与业务约定一致（对照 C-01） |

**样板（NCLCCT，2026-09-23）**：本机无 `NJCT.dll` / `model_hw.onnx` 时才云端下载 → `*.downloading` → 落盘正式路径并清理临时文件；本机已有则直接加载。

#### R3.2 检测结果 CSV（现场常被 Excel 打开）

| 检查 | 要求 |
|------|------|
| **勿直写被锁文件** | Excel 打开正式 CSV 时直接 `File.Append` / `StreamWriter` 易失败或写花；须有旁路策略 |
| **推荐两段式** | ① 新行先追加到旁路缓存（如同名 `.cache` 或等价）；② 再经**另一临时文件**合并「正式 CSV 已有内容 + 缓存」，成功后原子替换正式 CSV，清空 / 删除缓存 |
| **合并失败** | 保留缓存与旧正式文件，下次再合；禁止「合并失败仍截断正式 CSV」 |
| **表头** | 新建正式文件时写表头；合并时勿重复插表头 |

**样板（NCLCCT，2026-09-23）**：`Gap检测结果.csv` → 先写 `.cache` → 临时合并文件 → 覆盖正式 CSV（Excel 占用时不丢行）。

## 15. 如何新增条款（模板）

### 15.1 新增红线条款

1. 判断类别（A–H）；确实不属于任何一类时，追加新类别字母（`I` 起），并在 §9 开头类别说明与 §13 统计中补一行。
2. 编号取该类**最大序号 + 1**，追加到表格末尾；**不得插队、不得复用已废弃编号**。
3. 「❌」写可识别的具体代码形态，「✅」写可验证的具体做法；有升级条件的标 `P1↑` 并写明条件。
4. 需要长篇检查表或样板反例时，另起专项细则（§15.2），条款内写「详见 Rn」。
5. 按 §14 同步，并在 §16 追加一行。

复制下面一行改写即可：

```markdown
| X-NN | 触发场景 | 具体的错误写法 | 具体的正确做法（必要时：详见 Rn。升级条件：……） | P0 / P1 / P1↑ / P2 |
```

### 15.2 新增专项细则

```markdown
### Rn 场景名称——一句话目标

| 项 | 内容 |
|----|------|
| 关联条款 | X-NN |
| 触发场景 | 变更触及哪些类 / 目录 / API 时必读 |
| 级别 | 按 X-NN（或 P1↑ + 升级条件） |
| 案例 | 案例文件链接（可选） |

| 检查 | 要求 |
|------|------|
| **检查项** | 具体要求 |

**样板反例（项目，日期）**：现象 → 根因 → 修复要点。
```

### 15.3 废弃条款

不删除行，改为：`| ~~X-NN~~ | ~~原内容~~ | | 已废弃（日期，原因；由 Y-MM 取代） | — |`，保证历史审查报告中的编号仍可追溯。

### 15.4 新增写法约定

在第一篇对应章节内追加条目或新增 `§章.节`；若是硬性禁止项且会造成可靠性问题，应改为新增红线条款，而不是写在写法篇里。
