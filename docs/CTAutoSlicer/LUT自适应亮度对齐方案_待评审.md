## 1. 问题背景

当前主流程灰度相关步骤为：

1. 应用固定 **LUT 渲染预设**
2. 直方图峰谷半坡 → 拖 **红线**到目标列（靠右约 2/3）
3. 将 LUT 关键斜段 **中点水平拖到红线**（2c，保形状平移）

该方案能适应**同族产品峰区左右小漂移**，但产品结构/密度分布变化较大时：

- 直方图形态变化大，仅靠「预设 + 中点平移」难以保证渲染亮度落在 NJCT / 找点可用区间
- 送检侧虽有 `OfflineCtPreBrightenHelper`（ROI 均值/P50）作后处理兜底，但更希望在 **VG LUT 侧一次调对**

**目标**：在现有峰谷/红线能力之上，设计可评审的自适应算法——先定灰度范围（X），再用暗部/亮部区间驱动亮度（Y），必要时短闭环校验。

---

## 2. LUT 两点与坐标含义（前提共识）

业务上 LUT 关键段只标定 **两个控制点**（下方点、上方点），连成斜坡。

| 轴 | 含义 |
|----|------|
| **X（横）** | 体素灰度 / 密度输入。左=暗/低密度，右=亮/高密度。红线、峰谷均在此轴定位。 |
| **Y（纵）** | 映射输出强度（不透明度 / 显示亮度）。下=更透/更暗，上=更实/更亮。 |

| 控制点 | 主要作用 |
|--------|----------|
| **下方点** | 斜坡起点：从哪一档灰度开始变亮/变实；主要影响 **暗部** |
| **上方点** | 斜坡终点：到哪一档灰度接近最亮/最实；主要影响 **亮部** |

**重要**：整体亮度「达标」时，动下方点与动上方点**不可等价互换**：

- 抬下方点（Y↑ 或 X←）→ 偏 **提亮暗部**（噪点、低密度区易被抬起）
- 抬上方点（Y↑ 或 X←）→ 偏 **提亮亮部**（高光易过曝，暗部可能仍黑）

因此亮度验收不能只看单一全局均值，需区分暗部/亮部。

---

## 3. 总体策略（建议顺序）

```text
应用 LUT 预设
    → 峰谷分析 → 红线到位
    → 【阶段 A】按峰形规则摆好两点 X（灰度范围 / 窗位窗宽）
    → 截取渲染结果（建议：上视图或业务主体 ROI）
    → 【阶段 B】用暗部/亮部两套标准带判断误差
    → 按误差优先动对应点的 Y（必要时极小步微调 X）
    → 有界短闭环（或开环估一次 + 一次校验）
    → 失败则告警 + 沿用现有离线提亮兜底
```

原则：

1. **先 X 后 Y**，降低窗宽与亮度耦合
2. **控制自由度尽量低**（优先窗中心 + 窗宽；亮度再分暗/亮两点 Y）
3. **迭代有上限**，不在产线死循环拖 UIA
4. 与现有 2b/2c **并存扩展**，不废除峰谷红线逻辑

## 4. 阶段 A：灰度范围（X）——候选规则

### 4.1 现状（已实现）

- 预设后标定关键段两端 `LutSegmentPoint1/2`
- 中点水平拖到 `TargetScreenX`（红线）
- **保两点相对几何（形状/间距）**，仅整体平移

### 4.2 讨论中的增强（待定）

在预设 + 红线基础上，用峰形定 **窗宽**，而非永远死守预设间距：

| 符号 | 含义（与现网一致） |
|------|-------------------|
| \(V\) | 两最高尖峰之间的波谷（左线） |
| \(R\) | 红线 / 目标线 = \(V + (P_\text{right}-V)\times 2/3\) |
| \(D\) | \(D = R - V\)（红线到波谷的水平距离） |

**提议构造**：

- 以红线 \(R\) 为参考中心
- 半宽取 \(D\)（或 \(k\cdot D\)）
- 下方点目标 \(X_L = R - W/2\)，上方点目标 \(X_R = R + W/2\)
- 其中 \(W = \mathrm{clamp}(2\cdot D,\ W_{\min},\ W_{\max})\)（或 \(W = \mathrm{clamp}(\alpha\cdot(P_\text{right}-V),\ \ldots)\)）
- 摆 X 时 **Y 先保持预设标定高度**

当 \(W = 2D\) 且未钳制时：\(X_L \approx V\)（落在波谷），\(X_R = R+D\)（相对红线与波谷对称，会落到右峰更右侧一截）。

### 4.3 对该构造的评审意见（已记录）

| 项 | 说明 |
|----|------|
| 优点 | 窗宽跟随当前产品直方图；波谷锚点与现有左线一致；可计算、可落日志 |
| 风险 | 红线本身靠右 2/3，对称半宽 \(D\) 会使上点偏右、窗偏宽；双峰过近/过远时 \(D\) 极端 |
| 实现注意 | 若最终就是 \(R\pm W/2\)，**不必**先拖中点再重摆两端；一次算端点目标即可 |
| 建议 | \(D\) 作初值，必须加 \(k\)、\(W_{\min}\)、\(W_{\max}\)；真机核对「上点 = 红+\(D\)」是否过宽 |

### 4.4 建议落成的 X 规则（评审首选稿）

```text
1) 应用预设
2) 峰谷 → 得到 V、R、D=R-V
3) W = clamp(2·D, Wmin, Wmax)   // 或 clamp(α·(右峰-V), ...)；α/Wmin/Wmax 待真机标定
4) 下点 X = R - W/2，上点 X = R + W/2（Y 暂不变）
5) UIA：分别拖两端到目标（或经验证的等价拖法）；渲染稳定后进入阶段 B
```

相对「仅中点平移」：换型适应更强，但会改变预设斜坡宽度，需用合格样张回归对比度。

## 5. 阶段 B：亮度（Y）——双区间判断

### 5.1 是否需要两个区间？

**需要。** 仅全局均值会「达标但观感错误」。

| 区间 | 建议指标（待定具体阈值） | 决策 |
|------|--------------------------|------|
| 暗部 | 主体 ROI 低分位（如 P10～P25）或暗区均值 | 越界 → 优先动 **下方点 Y** |
| 亮部 | 高分位（如 P75～P90）或亮区均值 | 越界 → 优先动 **上方点 Y** |
| 总闸 | ROI 均值或 P50 | 总验收 / 双端同向微调触发 |

**比较对象**：建议用 **渲染后的上视图（或与 NJCT 同视角）业务 ROI**，不要只用直方图柱高判断「过暗/过亮」。

**参考来源**（二选一或组合，待定）：

- 一张（或一族）合格标准图提取目标带
- 产品族配置表：暗部/亮部允许区间

### 5.2 调整策略（建议）

| 观测 | 动作 |
|------|------|
| 仅暗部过暗 | 下方点 Y↑（小步）；禁止大步只拧上点充数 |
| 仅暗部过亮 | 下方点 Y↓ |
| 仅亮部过暗 | 上方点 Y↑ |
| 仅亮部过亮 | 上方点 Y↓ |
| 暗部、亮部同向偏离 | 两点 Y 同向小步，或整体微移 X（窗位） |
| 暗部过暗且亮部过亮（对比过强） | 优先收窗宽或降上点/抬下点的相对差，勿单向猛抬均值 |

步长、最大迭代次数、灵敏度系数需真机辨识；目标 **开环估一次 + 至多 1～2 次校验**，避免长闭环拖垮节拍。

## 7. 推荐流程（汇总伪代码）

```text
ApplyPreset()
CaptureHistogramRoi() → Peaks → DragRedLineTo(R)

# 阶段 A：灰度范围
D = R - V
W = clamp(2 * D, Wmin, Wmax)
DragLutPoint(Lower,  x = R - W/2, y = Y_preset_lower)
DragLutPoint(Upper,  x = R + W/2, y = Y_preset_upper)
WaitRenderStable()

# 阶段 B：亮度
img = CaptureRenderRoi()   # 上视图/主体 ROI
dark  = MeasureDarkBand(img)
bright = MeasureBrightBand(img)

for i in 1..MaxIter:
    if InBand(dark) and InBand(bright) and InBand(mean): break
    if dark too low:   Nudge(Lower.Y, +step)
    if dark too high:  Nudge(Lower.Y, -step)
    if bright too low: Nudge(Upper.Y, +step)
    if bright too high:Nudge(Upper.Y, -step)
    WaitRenderStable(); re-measure
else:
    LogWarn + 允许后续 OfflineCtPreBrighten 兜底
```

## 10. 建议的验证步骤（若批准实施）

1. 固定 3～5 个「合格 / 偏暗 / 偏亮 / 双峰间距极端」样件
2. 仅开阶段 A（PeakDerived 窗宽），对比现网 2c 的对比度与找点稳定性
3. 再开阶段 B（双区间 Y），记录迭代次数与最终暗/亮指标
4. 关闭自适应走兜底，确认软失败不阻断厚板/3-2-1
5. 写入单测按钮（建议挂在现有「测试直方图灰度调整」旁）
