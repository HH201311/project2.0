# 新增业务模块上手指南

> 适用分支：`develop`  
> 目标：在不深入框架源码的前提下，独立完成「新增一个业务页面并在左侧菜单显示」  
> 参考示例：LiWeiTest（`VM_TestPage` + `TestPage`）  
> 官方模板：`VM_DevelopProjectDemoPage` + `DevelopProjectDemoPage`

---

## 一、你要做的是什么

在 SUNWODA 平台上，一个业务模块 = **两个文件对**：

| 文件 | 放哪里 | 干什么 |
|------|--------|--------|
| `VM_XxxPage.cs` | `ViewModels/Pages/<项目名>/` | 页面逻辑、数据、读数据库 |
| `XxxPage.xaml` + `XxxPage.xaml.cs` | `Views/Pages/<项目名>/` | 页面长什么样 |

平台会自动把 ViewModel 和 View 配对，把页面注册进菜单（前提是数据库里启用了）。

**你只需要新建这 3 个文件，改数据库开关，编译运行。**

---

## 二、命名规则（最容易踩坑）

以项目名 `LiWeiTest`、页面名 `TestPage` 为例：

```
ViewModel 类名：  VM_TestPage
View 类名：       TestPage          （去掉 VM_ 前缀）
ViewModel 路径：  ViewModels/Pages/LiWeiTest/
View 路径：       Views/Pages/LiWeiTest/
```

三个名字必须对得上：

| 位置 | 写什么 |
|------|--------|
| ViewModel 类名 | `VM_TestPage` |
| `TestPage.xaml` 第一行 `x:Class` | `SUNWODA_SEVB.Views.Pages.LiWeiTest.TestPage` |
| `TestPage.xaml.cs` 类名 | `public partial class TestPage` |

**常见错误：** `x:Class` 写成 `testPage`（小写），`.cs` 写成 `TestPage` → 编译报「不存在 InitializeComponent」。

## 三、完整流程（按顺序做）

### 步骤 1：新建 ViewModel 文件

**路径：** `SUNWODA_SEVB/ViewModels/Pages/<项目名>/VM_XxxPage.cs`

**最少要写的内容：**

```csharp
using SUNWODA_SEVB.Core.Attributes;
using SUNWODA_SEVB.Core.Common;

namespace SUNWODA_SEVB.ViewModels.Pages.LiWeiTest
{
    [Module("VM_TestPage", "LiWei测试页面")]
    public class VM_TestPage : ViewModelBase
    {
    }
}
```

**每一项的含义：**

| 写法 | 含义 |
|------|------|
| `[Module("VM_TestPage", "LiWei测试页面")]` | 告诉平台「这是一个业务页面」 |
| 第一个参数 | 模块 ID，导航和数据库里都用这个名字 |
| 第二个参数 | 左侧菜单上显示的中文名 |
| 继承 `ViewModelBase` | 所有业务页的统一基类，提供属性刷新、生命周期等方法 |
| `public class` | 必须 public，否则平台扫描不到 |

---

### 步骤 2：新建 View 文件（界面）

**两个文件：**

- `SUNWODA_SEVB/Views/Pages/<项目名>/XxxPage.xaml` — 界面布局
- `SUNWODA_SEVB/Views/Pages/<项目名>/XxxPage.xaml.cs` — 代码后置

**XAML 最少内容：**

```xml
<Page
    x:Class="SUNWODA_SEVB.Views.Pages.LiWeiTest.TestPage"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    Title="TestPage">

    <Grid Margin="24">
        <TextBlock Text="{Binding BindingString}" FontSize="28" />
    </Grid>
</Page>
```

**code-behind 最少内容：**

```csharp
using System.Windows.Controls;

namespace SUNWODA_SEVB.Views.Pages.LiWeiTest
{
    public partial class TestPage : Page
    {
        public TestPage()
        {
            InitializeComponent();
        }
    }
}
```

**每一项的含义：**

| 写法 | 含义 |
|------|------|
| `x:Class="...TestPage"` | 声明这个 XAML 对应哪个 C# 类，必须和 `.cs` 类名完全一致 |
| `partial class TestPage` | 和 XAML 合成一个完整类；`InitializeComponent()` 由 XAML 编译器自动生成 |
| `{Binding BindingString}` | 界面文字绑定到 ViewModel 的 `BindingString` 属性 |
| 继承 `Page` | WPF 页面类型，主窗口中间区域用它来切换不同业务页 |

**.cs 文件一般只写构造函数，业务逻辑放在 ViewModel，不要写在 code-behind。**

---

### 步骤 3：在 ViewModel 里加绑定属性和常用服务

界面要显示的数据，写在 ViewModel 的属性里，用 `SetProperty` 才能刷新界面。

**示例：**

```csharp
private string? _bindingString;

public string? BindingString
{
    get => _bindingString;
    set => SetProperty(ref _bindingString, value);
}

public VM_TestPage(
    ILoggerService<VM_TestPage> logger,
    IGlobalSettingRepository globalSettingRepository)
{
    _logger = logger;
    _globalSettingRepository = globalSettingRepository;
}

public override void OnInitialize()
{
    BindingString = "LiWei 测试页面";
    base.OnInitialize();
}
```

**常用注入服务（写在构造函数参数里，不要自己 new）：**

| 服务 | 用途 |
|------|------|
| `ILoggerService<T>` | 写日志 |
| `IGlobalSettingRepository` | 读全局配置（如当前用户、默认项目） |
| `IWorkSpaceProjectRepository` | 读模块是否启用 |

**生命周期方法（按需重写）：**

| 方法 | 什么时候执行 | 适合做什么 |
|------|--------------|------------|
| `OnInitialize()` | 页面 ViewModel 第一次创建 | 设默认值 |
| `OnNavigatedTo()` | 每次点菜单进入页面 | 读数据库、刷新界面数据 |
| `OnNavigatedFrom()` | 离开页面 | 停定时器、清理订阅 |

---

### 步骤 4：编译项目

1. 确认 3 个文件路径和命名无误  
2. Visual Studio：**生成 → 重新生成解决方案**  
3. 首次克隆项目需先 **还原 NuGet 包**（`dotnet restore` 或 VS 菜单「还原 NuGet 程序包」）  
4. 编译必须 **0 错误**，否则菜单不会出现

---

### 步骤 5：在数据库里启用模块

首次启动应用时，平台会自动在数据库 `workspace_project` 表里插入你的模块记录，但 **默认不启用**（`is_enabled = 0`）。

在 MySQL 中执行（一条一条执行，不要多条粘在一起）：

```sql
USE sunwoda_demo;

-- 先查有没有这条记录
SELECT vm_class_name, is_enabled
FROM workspace_project
WHERE vm_class_name = 'VM_TestPage';

-- 启用模块（vm_class_name 必须和 ViewModel 类名一致，不是 TestPage）
UPDATE workspace_project
SET is_enabled = 1
WHERE vm_class_name = 'VM_TestPage';
```

| 字段 | 含义 |
|------|------|
| `vm_class_name` | 填 ViewModel 类名，如 `VM_TestPage` |
| `is_enabled` | `1` = 显示在菜单；`0` = 不显示 |

---

### 步骤 6：确认主窗口类型

只有使用 **通用主窗口** 时，所有已启用模块才会出现在菜单。

```sql
SELECT name, value FROM global_setting WHERE name = 'AppStartMainWindow';
```

| 值 | 效果 |
|----|------|
| `MainWindow` | 通用壳，显示所有已启用模块 ✅ |
| `CCTBMainWindow` | 涂布专用壳，只显示涂布模块，你的新页面不会出现 ❌ |

练手时请设为 `MainWindow`：

```sql
UPDATE global_setting SET value = 'MainWindow' WHERE name = 'AppStartMainWindow';
```

---

### 步骤 7：完整重启应用

改代码或改数据库后，必须 **完全退出程序再重新启动**（不要只靠热重载）。

启动后检查：
- 左侧菜单是否出现你写的显示名（如「LiWei测试页面」）
- 点进去界面是否正常显示
- 日志里是否有 `注册业务模块: VM_TestPage (LiWei测试页面)`

---

## 四、菜单不显示？按这个清单排查

全部满足才会出现在菜单：

- [ ] ViewModel 类上有 `[Module(...)]`
- [ ] 项目编译成功（0 错误）
- [ ] `x:Class` 与 `partial class` 名称完全一致（大小写也要一致）
- [ ] ViewModel 叫 `VM_XxxPage`，View 叫 `XxxPage`（去掉 `VM_`）
- [ ] 数据库 `workspace_project` 里 `vm_class_name` 正确且 `is_enabled = 1`
- [ ] `AppStartMainWindow` 为 `MainWindow`
- [ ] 修改后已完整重启应用

**日志提示：**

| 日志内容 | 说明 |
|----------|------|
| `注册业务模块: VM_TestPage (...)` | 成功 |
| `没有找到 ViewModel 对应的 View: VM_TestPage` | View 命名或路径不对 |

## 五、文件结构一览（以 LiWeiTest 为例）

```
SUNWODA_SEVB/
├── ViewModels/Pages/LiWeiTest/
│   └── VM_TestPage.cs          ← 逻辑 + [Module] + 绑定属性
└── Views/Pages/LiWeiTest/
    ├── TestPage.xaml           ← 界面布局
    └── TestPage.xaml.cs        ← partial class，一般只写构造函数
```

数据库：

```
sunwoda_demo.workspace_project
  vm_class_name = 'VM_TestPage'
  is_enabled    = 1
```

## 六、几个基础概念（够用手即可）

| 术语 | 一句话 |
|------|--------|
| MVVM | 界面（View）只管显示，逻辑和数据放 ViewModel，用 `{Binding}` 连接 |
| `[Module]` | 标记这个类是一个可被平台发现的业务页面 |
| `SetProperty` | 修改属性并通知界面刷新；直接赋值界面不会变 |
| `DataContext` | 页面的数据来源，平台会自动设为对应的 ViewModel |
| DI（依赖注入） | 构造函数里声明需要什么服务，平台自动传入，不要自己 `new` |
| `workspace_project` | 数据库表，控制模块是否在菜单显示 |
| `global_setting` | 数据库表，存全局配置（用户、主窗口类型等） |

## 七、后续扩展（当前阶段可不做）

| 需求 | 做法 |
|------|------|
| 加按钮、表格、图表 | 在 `.xaml` 里加控件，ViewModel 里加对应属性 |
| 按钮点击事件 | ViewModel 里写 `RelayCommand`，XAML 里 `{Binding 命令名}` |
| 复杂业务（PLC、通信、算法） | 抽到 `Services/Project/<项目名>/`，ViewModel 只负责界面和数据 |
| 对照学习 | 参考 `VM_DevelopProjectDemoPage` + `DevelopProjectDemoPage` |

框架底层（`ModuleManager`、`NavigationService` 等）可以等业务页能独立新增后再学，不影响日常开发。
